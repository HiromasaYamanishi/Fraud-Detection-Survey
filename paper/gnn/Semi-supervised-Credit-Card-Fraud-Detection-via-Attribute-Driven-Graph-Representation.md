# Semi-supervised Credit Card Fraud Detection via Attribute-Driven Graph Representation

**Authors:** Sheng Xiang, Mingzhi Zhu, Dawei Cheng, Enxia Li, Ruihui Zhao, Yi Ouyang, Ling Chen, Yefeng Zheng  
**Year:** 2023  
**Venue:** AAAI 2023

**Paper:** [arXiv](https://arxiv.org/abs/2412.18287)  
**PDF:** [arXiv PDF](https://arxiv.org/pdf/2412.18287)  
**Code:** [GitHub](https://github.com/finint/antifraud)

---

## [まとめ]

> **一言でいうと:** 取引をノードとし、同じカード保有者の過去の取引をエッジで結んだ時間的取引グラフを構築し、取引属性・時間的な関係・不正リスク情報を組み合わせて不正取引を検出する手法。

- **何をしたか:** 取引をノードとするTemporal Transaction Graphを構築し、GTANで過去の取引情報を集約。
- **新しい点:** 取引属性のEmbedding、Temporal Graph Attention、Risk Propagationを組み合わせる。
- **半教師あり学習:** ラベル付き取引だけでなく、大量の未ラベル取引もグラフ上の情報伝播に利用。
- **結果:** YelpChi、Amazon、FFSDの3データセットで既存手法と比較して高い性能を示した。

---

## [タスク概要]

**タスク:**  
クレジットカードなどの取引データから、各取引が**不正取引（Fraud）か正常取引か**を予測する。

**入力:**

- 各取引の属性情報
- 取引間の時間的な関係から構成したグラフ
- 一部の取引に付与されたFraud / Legitimateラベル

**出力:**  
各取引が不正である確率。

---

## [目的]

### 背景・課題

大規模な金融取引では、大量の取引に対して不正取引のラベルが十分に存在しない。

既存手法には主に以下の課題がある。

- ラベル付きデータだけでは、大量の未ラベル取引を十分に活用できない。
- 取引のカテゴリ属性を十分に活用できない。
- 取引の時間的な関係を十分に捉えられない。
- 不正取引に関連するリスク情報を十分に活用できない。

### 本研究の目的

**取引属性・時間的なグラフ構造・不正リスク情報を統合し、少量のラベルでも高精度に不正取引を検出すること。**

---

## [手法]

### 全体像

提案手法 **GTAN (Gated Temporal Attention Network)** は、以下の流れで不正取引を予測する。

```text
取引データ
   ↓
属性Embedding
   ↓
Temporal Transaction Graph構築
   ↓
Temporal Graph Attention
   ↓
Attribute-driven Gated Residual
   ↓
Risk Embedding / Propagation
   ↓
Fraud Prediction

GTANでは、単一の取引属性だけを見るのではなく、過去の取引・取引間の時間的関係・過去のリスク情報を組み合わせて現在の取引を判定する。

### Step 1. 取引属性をEmbedding

各取引が持つカテゴリ属性と数値属性をモデルに入力する。

カテゴリ属性については、属性ごとにEmbeddingを学習し、それらを組み合わせて取引のカテゴリEmbeddingを作成する。

その後、カテゴリ属性と数値属性を組み合わせて、各取引の初期特徴量を作る。

```
カテゴリ属性
   ↓
Attribute Embedding
   +
数値属性
   ↓
初期取引特徴量

```

これにより、カテゴリ型の取引情報もニューラルネットワークで扱えるベクトル表現に変換する。

### Step 2. Temporal Transaction Graphを構築

各取引を1つのノードとして扱い、同じカード保有者による取引の時間的な関係を有向エッジとして表現する。

#### ノード

1取引 = 1ノード

例えば、あるカード保有者について以下の取引が発生したとする。

* 10:00  取引A

* 12:00  取引B

* 15:00  取引C

現在の取引を予測するときには、それより前に発生した取引を過去の取引として利用する。

#### エッジ

過去の取引から現在の取引に向かって、時間方向のエッジを構成する。

概念的には、

```
過去の取引
    ↓
現在の取引

```

という構造になる。

例えば、過去の取引A・Bを利用して現在の取引Cを予測する場合、

```
A ──→ C
B ──→ C

```

のように、過去取引から現在取引へ情報を伝播させる。

> **注意:** 論文が明示しているのは「同じカード保有者の過去の取引をTemporal Neighborとして利用する」という構造であり、すべての過去取引同士を完全結合することではない。したがって、以下の図は時間方向の関係を説明するための概念図である。

```
10:00        12:00        15:00
  A            B            C
  └────────────┬────────────┘
               ↓
          現在の取引C

```

また、過去の取引をすべて利用するのではなく、Temporal Neighborをサンプリングしてエッジ数を制限する。

これにより、取引数が非常に多い場合でも計算量・メモリ使用量を抑える。

実験では、1ノードあたりのTemporal Edge数を1〜10の範囲で検討し、デフォルトでは6を使用している。

#### 未来の情報は利用しない

不正検知では未来の取引を使って現在の取引を予測すると、情報漏洩（data leakage）が発生する。

そのため、

```
過去の取引
    ↓
現在の取引

```

という時間方向のみの情報伝播を行い、現在の取引より後に発生した取引は予測に利用しない。

### Step 3. Temporal Graph Attentionで過去取引を集約

構築したTemporal Transaction Graph上で、Temporal Graph Attentionを適用する。

現在の取引について、過去のTemporal Neighborから特徴を集約する。

例えば、

```
             過去取引A
                 │
                 ↓
過去取引B ──→ 現在取引C ←── 過去取引D

```

のような関係がある場合、A・B・Dの情報を利用してCの特徴を更新する。

ただし、すべての過去取引を同じ重要度で扱うわけではない。

Attentionによって各過去取引の重要度を学習する。

つまり、

**「現在の取引Cを判断するうえで、どの過去取引が重要なのか？」**

をモデル自身が学習する。

```
過去取引A ── weight 0.1 ──┐
過去取引B ── weight 0.7 ──┼→ 集約 → 取引CのGraph Feature
過去取引D ── weight 0.2 ──┘

```

このように、現在の取引と関連性の高い過去取引をより強く反映できる。

### Step 4. Attribute-driven Gated Residual

Temporal Graph Attentionによって得られたグラフ特徴だけを利用するのではなく、元の取引属性とグラフから得られた特徴を組み合わせる。

具体的には、

* 元の取引属性

* 数値属性

* Temporal Graphから得られた特徴

を利用する。

Gateによって、

* 「元の取引属性をどの程度残すか」

* 「グラフから得られた情報をどの程度利用するか」

を調整する。

概念的には、

```
元の取引属性 ───────┐
                    ↓
                  Gate
                    ↓
グラフ特徴 ─────────┘
                    ↓
             統合された特徴

```

となる。

これにより、グラフ情報だけに依存せず、元々の取引属性も保持しながらグラフ情報を利用できる。

### Step 5. Risk Embeddingによるリスク情報の伝播

GTANでは、取引のラベル情報もグラフ上の情報として利用する。

取引の状態を以下の3種類に分類する。

* Fraud

* Legitimate

* Unlabeled

それぞれにRisk Embeddingを割り当てる。

```
Fraud       → Risk Embedding
Legitimate  → Risk Embedding
Unlabeled   → Risk Embedding

```

そして、グラフ上でこのRisk Embeddingを伝播させる。

例えば、

```
過去取引A：Fraud
       │
       ↓
過去取引B：Legitimate
       │
       ↓
現在取引C：Unlabeled

```

のような場合、過去取引のRisk情報を現在取引の予測に利用する。

これにより、

**「この取引の周辺に、過去に不正と判定された取引がどの程度存在するのか？」**

といった情報を予測に利用できる。

#### Label Leakageへの対策

Risk Embeddingに予測対象自身のラベルを直接入力すると、正解をそのままモデルに与えることになってしまう。

例えば、

```
現在取引C = Fraud

```

という正解ラベルをそのままCのRisk Embeddingとして入力すると、Label Leakageが発生する。

そのため、学習時には中心ノード（現在の予測対象）のRisk Embeddingをマスクする。

```
中心ノードのRisk情報
        ↓
      Mask
        ↓
モデルには直接与えない

```

これにより、周辺取引のリスク情報を利用しつつ、予測対象自身の正解ラベルが直接入力されることを防ぐ。

### Step 6. Fraud Prediction

最後に、

* 取引自身の属性

* 過去取引から得られたTemporal Graph Feature

* 過去取引から得られたRisk Information

を統合する。

統合された特徴を2層MLPに入力し、各取引の不正確率を予測する。

```
取引属性
   +
Temporal Graph Feature
   +
Risk Information
        ↓
      GTAN
        ↓
     2-layer MLP
        ↓
Fraud Probability

```

## \[実験\]

### データセット

以下の3つのデータセットを用いて評価する。

| 

| **Dataset** | **#Nodes** | **#Edges** | **#Fraud** | **#Legitimate** | **#Unlabeled** | 
| **YelpChi** | 45,954 | 7,739,912 | 6,677 | 39,277 | 0 | 
| **Amazon** | 11,948 | 8,808,728 | 821 | 11,127 | 0 | 
| **FFSD** | 1,820,840 | 31,619,440 | 33,858 | 141,861 | 1,645,121 | 

特にFFSDでは、

* `#Nodes = 1,820,840`

* `#Unlabeled = 1,645,121`

となっており、大量の未ラベル取引が存在する。

このため、半教師あり学習による未ラベルデータの活用を評価するのに適したデータセットとなっている。

### 評価指標

以下の3つの指標を使用する。

* AUC (Area Under the ROC Curve)

* F1 Score

* AP (Average Precision)

### 比較手法

以下の既存手法と比較する。

* GEM

* FdGars

* Player2Vec

* Semi-GNN

* GraphSAGE

* GraphConsis

* CARE-GNN

* PC-GNN

## \[結果\]

### 定量結果

GTANの結果は以下の通り。

| **Dataset** | **AUC** | **F1** | **AP** | 
| **YelpChi** | 0.9241 | 0.7988 | 0.7513 | 
| **Amazon** | 0.9630 | 0.9213 | 0.8838 | 
| **FFSD** | 0.7616 | 0.6764 | 0.5767 | 

論文では、既存手法と比較してAUCについて、YelpChi・Amazon・FFSDでそれぞれ少なくとも、

* YelpChi: 10%

* Amazon: 0.5%

* FFSD: 6%

の改善を報告している。

APについても、

* YelpChi: 27%

* Amazon: 2.9%

* FFSD: 12.8%

の改善を報告している。

### 半教師あり学習

GTANが少量のラベルでも有効に機能するかを確認するため、ラベル付き学習データの割合を変化させて実験している。

ラベル付きデータの割合を、10%, 20%, 30%, ..., 80% のように変化させて評価する。

その結果、ラベル付きデータが少ない条件でもGTANは高い性能を維持した。

特に、10%程度のラベル付きデータでも有効に機能することを示している。

これは、実際の不正検知において、

```
大量の取引
      +
少量のラベル付き不正取引
      +
大量の未ラベル取引

```

という状況を想定した場合に、グラフ構造を利用して未ラベルデータを活用できることを示している。

## \[考察\]

### 1. 過去取引を利用することで取引単体では捉えにくい情報を利用できる

通常の取引分類では、

```
現在の取引
   ↓
Fraud / Legitimate

```

というように、現在の取引自身の特徴を中心に判断する。

一方GTANでは、

```
過去の取引
   ↓
現在の取引

```

という時間的な関係を利用する。

そのため、単一の取引属性だけでは分かりにくい不正パターンを捉えられる。

### 2. Attentionによって重要な過去取引を重視できる

すべての過去取引を同じ重要度で扱うのではなく、Temporal Graph Attentionによって重要度を学習する。

そのため、

```
過去取引A → 重要度 低
過去取引B → 重要度 高
過去取引C → 重要度 中

```

のように、現在の取引の予測に重要な過去取引をより強く反映できる。

### 3. Risk Embeddingによって過去の不正情報を利用できる

過去にFraudと判定された取引の情報をRisk Embeddingとしてグラフ上で利用する。

そのため、

「この取引の周辺に、過去に不正と判定された取引が存在するか？」

という情報を予測に利用できる。

### 4. 未ラベルデータをグラフ構造の中で利用できる

FFSDでは1.6M件以上の未ラベル取引が存在する。

GTANでは、これらの取引を単純に捨てるのではなく、グラフ上のノードとして利用する。

そのため、

```
少量のLabel
      +
大量のUnlabeled Data
      ↓
Graph-based Information Propagation
      ↓
Fraud Detection

```

という半教師あり学習が可能になる。

## \[Limitations\]

* 取引間の関係を利用するため、Temporal Transaction Graphの構築方法が性能に影響する。

* 1取引あたりのTemporal Edge数を増やすと、より多くの過去情報を利用できる一方で、計算コストも増加する。

* 大規模な取引グラフを扱うため、実際の金融システムへの適用では計算量・メモリ・推論速度などの制約を考慮する必要がある。

* 実運用では、モデル性能だけでなく、リアルタイム性やシステム運用上の制約も考慮する必要がある。
